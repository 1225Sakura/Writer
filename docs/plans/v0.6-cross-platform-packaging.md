## §2 当前限制

### 2.1 electron-builder 配置（v0.5）

文件：`electron/electron-builder.yml`（或 `package.json` 中 builder 字段）：

```yaml
# 当前 v0.5 配置（推断）
appId: com.writer.app
productName: Writer
directories:
  buildResources: public
  output: release/${version}
files:
  - dist/**/*
  - package.json
  - "!**/*.map"
asar: true
win:
  target:
    - target: nsis
      arch: [x64]
  icon: public/icon.ico
mac:
  # 未配置
linux:
  # 未配置
```

**缺失**：mac/linux target 配置 + asarUnpack 规则。

### 2.2 Python 后端打包（v0.5）

当前 backend 用 Python venv：

```python
# electron/main.ts:201-301 启动 Python 子进程
subprocess.spawn(['./venv/Scripts/python.exe', '-m', 'uvicorn', 'app.main:app'], {...})
```

**Windows 路径**：`./venv/Scripts/python.exe`
**macOS 路径**：`./venv/bin/python`
**Linux 路径**：`./venv/bin/python`

**当前实现**：硬编码 Windows path。**Linux/macOS 必坏**。

### 2.3 ffmpeg.dll 硬编码

F-E-14：electron-builder 默认在 Windows 输出 `ffmpeg.dll`。但 macOS/Linux 使用 `ffmpeg`（无扩展名）。当前代码硬编码 `.dll`。

### 2.4 用户数据目录

| OS | 路径 |
|----|------|
| Windows | `%APPDATA%\writer` |
| macOS | `~/Library/Application Support/writer` |
| Linux | `~/.local/share/writer` (XDG) 或 `~/.config/writer` |

Electron `app.getPath('userData')` 自动处理，但 **写入 .env 文件**（auth init key）路径需测试。

### 2.5 CI matrix 限制

- macos-latest runner ≈ 4 cores / 8GB，10-20 分钟冷启动
- Linux 矩阵用 ubuntu-latest，但未测 fedora/arch/manjaro
- Apple Silicon (M1/M2) 需 macos-14 runner（GitHub Actions 提供）
- Intel macOS 需 macos-13 runner

## §3 Linux 打包方案

### 3.1 electron-builder target

```yaml
linux:
  target:
    - target: AppImage
      arch: [x64]
    - target: deb
      arch: [x64]
    # - target: rpm       # Phase 2+ （需要 rpm-build 工具链）
    # - target: pacman    # Phase 3+ （仅 Arch 用户）
  category: Office
  icon: public/icon.png  # 需要 512x512 PNG（Windows .ico 不够）
  synopsis: AI-assisted Chinese novel writer
  description: |
    Writer is a local desktop application for Chinese web novel authors.
    It uses AI to assist with world-building, character design, and prose generation.
  desktop:
    entry:
      Name: Writer
      Comment: AI-assisted novel writer
      Categories: Office;TextEditor;
      Keywords: novel;writing;AI;
  mimeTypes:
    - text/plain
    - text/html
```

### 3.2 AppImage 优缺点

**AppImage**（推荐主目标）：
- ✅ 单文件 portable（用户无需安装）
- ✅ 跨发行版（Ubuntu / Fedora / Arch 都可运行）
- ✅ 不需要 root 权限
- ❌ 首次启动较慢（FUSE mount）
- ❌ 不在系统 PATH

**deb**：
- ✅ Ubuntu/Debian 用户熟悉
- ✅ 系统级安装 + 自动更新
- ❌ 仅限 Debian 系（不覆盖 Fedora/Arch）

**目标**：AppImage（主） + deb（辅） + 未来加 rpm（Phase 2+）

### 3.3 Linux 资源处理

```yaml
# electron-builder.yml
asar: true
asarUnpack:
  - "**/node_modules/sharp/**/*"     # sharp 原生 binding
  - "**/ffmpeg"                      # ffmpeg 二进制（如果打包）
  - "**/venv/**/site-packages/**/*"  # Python 依赖
```

**Linux 路径硬编码修复**：
```python
# electron/main.ts
import sys
import os

def get_python_executable():
    if sys.platform == 'win32':
        return os.path.join('venv', 'Scripts', 'python.exe')
    elif sys.platform == 'darwin':
        return os.path.join('venv', 'bin', 'python')
    else:  # linux
        return os.path.join('venv', 'bin', 'python')
```

### 3.4 ffmpeg 路径修复（F-E-14）

```typescript
// electron/main.ts (改进版)
function getFFmpegPath(): string {
  const platform = process.platform
  if (platform === 'win32') return path.join(resourcesPath, 'ffmpeg.dll')
  if (platform === 'darwin') return path.join(resourcesPath, 'ffmpeg')
  return path.join(resourcesPath, 'ffmpeg')  // Linux
}

function getFFmpegName(): string {
  return process.platform === 'win32' ? 'ffmpeg.dll' : 'ffmpeg'
}
```

## §4 macOS 打包方案

### 4.1 electron-builder target

```yaml
mac:
  category: public.app-category.productivity
  icon: public/icon.icns   # 需要 .icns（macOS 专用格式）
  target:
    - target: dmg
      arch:
        - x64
        - arm64
    - target: zip
      arch:
        - universal  # universal binary（Intel + Apple Silicon）
  hardenedRuntime: true
  gatekeeperAssess: false
  identity: null  # 开发阶段无需 signing
  notarize: false  # 公开发布需打开
  extendInfo:
    NSHumanReadableCopyright: "© 2026 Writer"
    LSApplicationCategoryType: public.app-category.productivity
    NSHighResolutionCapable: true
```

### 4.2 Universal Binary

**两种构建路径**：

1. **arm64 + x64 双构建**（默认）：分别打两个 .app，dmg 内含两者
2. **universal 单构建**：用 `lipo` 合并两个 binary 成 universal

**推荐 universal**：

```bash
# electron-builder 自动处理（在 macos-latest runner 上）
lipo -create \
  /path/to/writer-arm64.app/Contents/MacOS/writer \
  /path/to/writer-x64.app/Contents/MacOS/writer \
  -output /path/to/writer-universal.app/Contents/MacOS/writer
```

**优势**：
- 单 dmg 覆盖 Intel + Apple Silicon
- 用户体验更好（无"选择正确版本"步骤）
- 节省 50% 下载量（vs 提供两个独立 dmg）

**权衡**：
- universal binary 体积 = arm64 + x64（无去重）
- 构建时间 ~ 2x

### 4.3 Code Signing + Notarization

**开发阶段**：
- `identity: null`（无 signing）
- `notarize: false`（无 Apple 公证）
- macOS 用户首次启动会看到"未识别开发者"警告
- 用户需 System Preferences → Security → 允许

**生产阶段**：
- 需要 Apple Developer ID（$99/年）
- `identity: "Developer ID Application: Your Name (TEAMID)"`
- `notarize: true`（自动提交到 Apple 公证服务）
- 配置 `APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` env vars in CI

**实施步骤**：
1. 注册 Apple Developer Program
2. 创建 Developer ID Application certificate
3. 在 CI 配置 `CSC_LINK`（base64 编码的 p12）+ `CSC_KEY_PASSWORD`
4. 配置 `APPLE_ID` + `APPLE_APP_SPECIFIC_PASSWORD` + `APPLE_TEAM_ID`
5. 测试 signed + notarized dmg 在干净 macOS 上双击启动

### 4.4 macOS 沙盒 / Hardened Runtime

```yaml
mac:
  hardenedRuntime: true      # 必需（公证前提）
  entitlements: build/entitlements.mac.plist
  entitlementsInherit: build/entitlements.mac.plist
```

```xml
<!-- build/entitlements.mac.plist -->
<plist version="1.0">
<dict>
  <key>com.apple.security.cs.allow-jit</key><true/>
  <key>com.apple.security.cs.allow-unsigned-executable-memory</key><true/>
  <key>com.apple.security.network.client</key><true/>
  <key>com.apple.security.network.server</key><true/>
  <key>com.apple.security.files.user-selected.read-only</key><true/>
</dict>
</plist>
```

### 4.5 macOS 路径修复

```python

```

## §5 Python venv 跨平台打包

### 5.1 当前 v0.5 方案

- 用户安装 app → electron 触发 `python -m venv venv` → `pip install -r requirements.txt`（首次启动 5-10 分钟）
- 之后启动 → `./venv/bin/python -m uvicorn app.main:app`（秒级）

**问题**：首次启动慢 + 用户必须能联网下载 Python deps。

### 5.2 v0.6 改进方案

**选项 A：PyInstaller bundle**
- 优点：单 binary，无 venv
- 缺点：40MB+ binary；调试困难；某些 package 不兼容

**选项 B：conda-pack / venv-pack**
- 优点：保留 venv 结构
- 缺点：仍需解包；体积大

**选项 C：pigar / pipenv bundle**
- 优点：pip wheel 直接打包
- 缺点：依赖 .whl 仓库

**推荐 v0.6 方案**：

```
Phase 1：继续用 venv + 启动时 pip install（与 v0.5 一致）
Phase 2：预编译 wheels + cache（如果用户网络慢）
Phase 3：考虑 PyInstaller（如果启动速度是瓶颈）
```

**v0.6.0 范围**：仅修复跨平台路径硬编码（§3.3 + §4.5）。

### 5.3 requirements.txt 跨平台

```python
# requirements.txt
# macOS/Linux-specific
# cryptography 是 OS-agnostic；anthropic SDK 同理
# 无需分开 requirements-mac.txt vs requirements-linux.txt
```

**Linux 特有依赖**：
- `python3-dev`（编译 cryptography 时需要）
- `libffi-dev`（cffi 编译需要）
- `libssl-dev`（cryptography 需要）

**解决方案**：在 PyPI 上 `cryptography` 有 prebuilt wheels for linux x86_64 + aarch64 + macOS x86_64 + arm64。**无需源码编译**。

### 5.4 venv 创建脚本

```python
# electron/main.ts → ensureBackend()
async function ensureBackend() {
  const venvPath = path.join(resourcesPath, 'venv')
  if (!fs.existsSync(venvPath)) {
    log.info('Creating venv...')
    await exec(`${pythonCmd} -m venv ${venvPath}`)
  }
  
  // 跨平台 pip path
  const pipCmd = process.platform === 'win32'
    ? path.join(venvPath, 'Scripts', 'pip.exe')
    : path.join(venvPath, 'bin', 'pip')
  
  // 检查关键 deps
  const hasFastAPI = await checkImportable(venvPath, 'fastapi')
  if (!hasFastAPI) {
    log.info('Installing backend deps...')
    await exec(`${pipCmd} install -r requirements.txt`)
  }
}
```

## §6 CI Matrix 调整

### 6.1 当前 CI

`.github/workflows/build.yml`：
```yaml
strategy:
  matrix:
    os: [windows-latest, macos-latest, ubuntu-latest]
```

**当前各 OS 步骤**：
- windows-latest: build + test + dist:win
- macos-latest: build + test（无 dist）
- ubuntu-latest: build + test（无 dist）

### 6.2 v0.6 目标 CI

```yaml
name: Build

on:
  push:
    branches: [main, master]
  pull_request:
  workflow_dispatch:

jobs:
  build:
    name: Build & Test
    strategy:
      fail-fast: false
      matrix:
        include:
          - os: windows-latest
            python-version: '3.12'
            node-version: '20'
            package_target: 'dist:win'
          - os: macos-14  # Apple Silicon runner
            python-version: '3.12'
            node-version: '20'
            package_target: 'dist:mac'
          - os: ubuntu-latest
            python-version: '3.12'
            node-version: '20'
            package_target: 'dist:linux'

    runs-on: ${{ matrix.os }}
    defaults:
      run:
        working-directory: src/frontend

    steps:
      - uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'npm'
          cache-dependency-path: src/frontend/package-lock.json

      - name: Install frontend deps
        run: npm ci

      - name: Build frontend
        run: npm run build

      - name: Setup backend deps (Python venv)
        run: |
          python -m venv .venv
          .venv/Scripts/python.exe -m pip install -r requirements.txt   # Windows
          # .venv/bin/python -m pip install -r requirements.txt         # macOS/Linux

      - name: Run backend tests
        run: |
          .venv/Scripts/python.exe -m pytest ../backend/tests/ -v
          # .venv/bin/python -m pytest ../backend/tests/ -v

      - name: Install backend into Electron
        run: |
          cd ../backend
          .venv/Scripts/python.exe -m pip freeze > ../electron/requirements-lock.txt

      - name: Build Electron app
        run: npm run ${{ matrix.package_target }}
        working-directory: electron

      - name: Upload artifacts
        uses: actions/upload-artifact@v4
        with:
          name: writer-${{ matrix.os }}
          path: |
            release/*.exe        # Windows
            release/*.dmg        # macOS
            release/*.AppImage   # Linux
            release/*.deb
          retention-days: 14
```

### 6.3 关键差异

| OS | Runner | Python | 打包命令 |
|----|--------|--------|----------|
| Windows | windows-latest | 3.12 | `electron-builder --win nsis portable` |
| macOS | macos-14 | 3.12 | `electron-builder --mac dmg zip --arm64 --x64` |
| Linux | ubuntu-latest | 3.12 | `electron-builder --linux AppImage deb` |

### 6.4 排除 runner

**macos-13 (Intel runner)**：保留作为 x64-only 构建（如果需要分开 arm64 + x64 dmg）。

**macos-latest 默认**：通常是 macos-14（Apple Silicon）。需要 universal binary 时手动跑两个 runner。

### 6.5 cache 策略

```yaml
- name: Cache Python venv
  uses: actions/cache@v4
  with:
    path: |
      .venv
      ~/.cache/pip
    key: ${{ runner.os }}-pip-${{ hashFiles('requirements.txt') }}
    restore-keys: |
      ${{ runner.os }}-pip-
```

加速 CI：第二次跑复用 venv（pip install 5-10 分钟 → 0 秒）。

## §9 风险

### 9.1 Apple Silicon 兼容性

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| 部分 Python wheel 不含 arm64 | 中 | 检查关键 deps（cryptography / anthropic）；fallback x86_64 via Rosetta 2 |
| electron native modules 不兼容 | 中 | electron-forge 重新编译 arm64 |
| 测试覆盖不足 | 中 | macos-14 runner CI + 手动真机测试 |

### 9.2 Linux 发行版多样性

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| glibc 版本差异（Ubuntu 22 vs older） | 中 | AppImage 自带 glibc shim |
| Wayland vs X11 | 低 | Electron 自动处理 |
| 不同 desktop environment（GNOME / KDE / XFCE） | 低 | 测试最少 2 种 DE |

### 9.3 Code Signing 成本

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| Apple Developer ID $99/年 | 低 | 已是行业标准成本 |
| 公证失败（bug in build） | 中 | CI 自动 retry + 通知 |
| 公证慢（10-30 分钟） | 低 | 接受 |

### 9.4 跨平台 Python 依赖

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| 某些 pip 包无 Linux wheel | 低 | 大多数关键包都有 wheel |
| macOS arm64 wheel 缺失 | 低 | anthropic + cryptography 都有 |
| Linux musl libc（Alpine） | 低 | 不支持 Alpine（仅 glibc） |

### 10.1 功能验收

- ✅ Windows 11 + macOS 14 (M1/M2) + Linux Ubuntu 22.04 LTS 三 OS 完整 build + 打包 + 启动
- ✅ 每个 OS 上 e2e:cold-start 跑通
- ✅ 每个 OS 上 AI provider 测试通过
- ✅ universal binary 在 Intel + Apple Silicon Mac 都可运行

### 10.2 CI 验收

- ✅ `npm run dist:win` / `dist:mac` / `dist:linux` 三命令都成功
- ✅ 每个 OS 的 artifact 上传到 GitHub Actions
- ✅ workflow 文件自动测 3 OS

### 10.3 用户体验验收

- ✅ AppImage 用户体验：双击启动（无需 chmod）
- ✅ deb 用户体验：`sudo dpkg -i` + 启动菜单找到 Writer
- ✅ dmg 用户体验：双击挂载 + 拖入 Applications + 启动（首次需解除 Gatekeeper）

### 10.4 维护验收

- ✅ 跨平台 bug fix PR 有 CI 全 OS 绿灯才合并
- ✅ 每个 release artifact 包含 sha256 + size + version 元数据
- ✅ Release notes 列出每个 OS 的已知 issues
