| OAuth 2.0 RFC 6749 — WebSocket ticket pattern | https://datatracker.ietf.org/doc/html/rfc6749 | 推荐的 WS 短期 ticket 模式：HTTP `/auth/ws-ticket` 拿 `secrets.token_urlsafe(32)` opaque ticket；WS 升级时验证 + 一次性（`SET NX EX 300`）|

**核心冲突**（spec vs 权威源）：
- spec §5.1 P0-Sec2 完成判据列了 9 类拒绝输入但**漏禁 redirects**——攻击者可让 writer 后端先去 public host，response 301 → 内网。OWASP 明确"redirects must be blocked or re-validated"。
- spec §5.1 P0-Sec2 只校验输入 URL 的 host，**未要求 DNS resolve 后对每条 A/AAAA 做 global IP 校验**——典型 DNS rebinding 防御缺失（attack.com DNS 第一次解析 1.2.3.4 public，第二次 169.254.169.254 metadata）。
- spec §5.1 P0-Sec2 列了"WS ticket 一次性、≤ 5 分钟过期"但**未规定 atomic consume 机制**——race condition 下同一 ticket 可用两次；未规定 Origin 校验。
- spec §5.1 P0-Sec2 完成判据漏 `provider URL = http://169.254.169.254` 测例（AWS metadata 服务，最高优先级 SSRF 目标）。

### C.1 Attacker-perspective adversarial review
**status**：已收（f1c9d2e5a8b3746c0）

> "作为攻击者，重读整份 spec v0.3.1，列出 24h 内可触发的攻击面与 spec 未覆盖的边角。"

**已识别的可触发攻击面**：

1. **[CRITICAL, NEW] BYPASS_AUTH 跨 build 模式泄漏**
   - 场景：spec §0.1 + §5.1 P0-Sec1a 规定"BYPASS_AUTH=true 仅在 dev mode 允许"。但 `electron/main.ts` 通过 `import.meta.env.MODE` 区分 dev/prod，**而 main.ts 不直接消费 Vite 的 import.meta.env**（Electron 主进程是 Node.js 上下文）。attacker 可以：发布恶意 npm 包在 dev 时 hook `process.env.BYPASS_AUTH` 后用 `electron-builder` 打包成 prod 安装包，但 `process.env.BYPASS_AUTH` 在 prod build 仍可从外部注入（操作系统环境变量）。
   - **spec 漏洞**：spec 仅约束"默认 false"，未约束"prod build 强制忽略外部 env"（应改为"prod build 时编译期硬编码 `BYPASS_AUTH=false`，忽略 runtime env"）。
   - **action**：D.1.8 加固（详见后文）。

2. **[HIGH, NEW] P0-Hyg-cleanup 单文件不可 rollback**
   - 场景：spec 写"先 `git bundle create ... --all` backup"，然后 `git rm -r --cached` 220 个 `.omc/`。但 `git bundle restore` 是**整库恢复**——如果只想恢复某 1 个 `.omc/specs/2026-07-11-cleanup-design.md`，必须 `git bundle clone` 出新工作树、checkout 文件、cherry-pick。attacker 利用这点：提交阶段偷偷修改 1 个被 `.omc/` ignore 的文件路径（如 `.omc/plans/foo.md`）然后 cleanup，事后 rollback 失败。
   - **spec 漏洞**：backup bundle 不够；需要 **per-file selective restore** 流程文档化。
   - **action**：D.1.13 加固（详见后文）。

3. **[HIGH, NEW] IndexedDB 跨域攻击面**
   - 场景：spec §5.1 P0-Sec4a 修"setItem 错误吞掉"，但 IndexedDB 是 **per-origin**——attacker 在 Electron 渲染进程内嵌恶意 SVG `<image href="data:image/svg+xml;base64,...">` 触发 XSS（同源）后写恶意数据到 writer IDB。spec 未提及"如果 IDB 数据被篡改，启动时如何检测"。
   - **spec 漏洞**：spec 当前 P0-Sec4d 是"健康检查"但未提及"完整性校验"（如 HMAC 签名 IDB payload）。
   - **action**：D.2.6 建议改（详见后文）。

4. **[MEDIUM, NEW] Provider URL 白名单绕过**
   - 场景：spec §5.1 P0-Sec2 用"已知 provider host 白名单"——但 spec 未提及"自定义 provider"路径。如果 UI 提供"Custom provider"输入（peer `AIProviderPanel.tsx:175-181` 已 mention），用户填入 `https://my-proxy.attacker.com/v1/` → 后端 `httpx.AsyncClient(base_url=...)` → attacker 代理可记录所有 provider key + prompt。
   - **spec 漏洞**：spec 当前 SSRF 完成判据只测 9 类拒绝输入，未测"白名单外的 https host 是否仍被拒"。
   - **action**：D.1.4 已经在 SSRF 完成判据加测"未在白名单的 https host 被拒"；C.1 强化此点。

5. **[MEDIUM, NEW] AI log JSONL 文件权限**
   - 场景：spec §5.1 P0-Sec4c 写"opt-in 时强制 redact"，但 redact 只对内容字段生效，**未规定文件权限**。Electron `app.getPath('logs')` 在 Linux/macOS 默认 644（其他用户可读）。attacker 同机其他用户读 `ai-log.jsonl` → 即使 redact 字段，**剩余 metadata（时间戳、章节名、字数）**仍是隐私。
   - **spec 漏洞**：spec 未规定日志文件权限（应 600）+ owner-only access。
   - **action**：D.2.7 建议改。

6. **[LOW, NEW] pre-commit hook 钓鱼**
   - 场景：spec §5.1 P0-CI 写"pre-commit hook 安装脚本可幂等执行"。attacker 可在 `.git/hooks/pre-commit` 注入恶意脚本（per-repo hooks 不被 git 自动签），诱导协作者运行 install。
   - **spec 漏洞**：spec 未提及"hook 必须是 pre-commit 框架管理（hooks 在 `.git/hooks/` 而非 repo 内）"。
   - **action**：D.2.8 建议改（pre-commit 框架默认 hooks 在 `~/.cache/pre-commit/` 不在 repo，避免攻击）。

**attacker 视角总评**：spec v0.3.1 已修 6 条 P0 大面，但**6 条边角攻击面**需要补硬阻塞或建议改。**新增 2 项硬阻塞（D.1.8 + D.1.13），4 项建议改（D.2.6-D.2.9）**。

   - 论据：单人 + 无常驻 reviewer + 14 PR × （commit + push + e2e + wait CI + self-review + merge）= 约 30-45 min/PR × 14 = ~7-10 小时，仅 PR overhead。**加实际代码改动 4-6 周是合理，但 PR overhead 是真实税**。
   - **建议**：按 4 域合并为 3-4 PR：(i) CRUD 域（projects/chapters/drafts/outlines/rules）8 routers 1 PR；(ii) 实体域（characters/items/locations/factions/world_settings）5 routers 1 PR；(iii) AI 域（ai_provider/ai_generate/ai_review/ai_fill_fields/ai_rewrite_description/ai_generate_entity）6 routers 1 PR；(iv) chat WebSocket 1 PR。
   - **是否推翻 spec**：**是**——spec v0.3.1 §5.1 P0-Sec1b "每 router 1 PR" 必须改为"按域合并"。
   - **action**：D.2.4 推翻（详见后文）。

2. **[PUSHBACK] P0-Sec4d "手动 quota 测试" 不可自动化**
   - 论据：spec §4.5 P0-Sec4d 标 "unit + e2e + manual"，manual 部分要求"本地制造 quota exceeded 场景后启动应用"——attacker 没有 DevTools 配额工具，**DevTools 配额工具**实际可触发但跨平台行为不一致（Firefox 不支持）。
   - **建议**：用 `fake-indexeddb` 的 `setFakeStorageQuota(N)` + Playwright `chromium.launch({ args: ['--disable-features=...'] })` 模拟 quota。
   - **是否推翻 spec**：**否**——保留 manual + 加自动化覆盖。
   - **action**：D.2.10 建议改（manual 保留 + 加自动化）。

3. **[PUSHBACK] P0-CI pre-commit hook 安装摩擦**
   - 论据：spec §5.1 P0-CI 写"pre-commit hook 强制 doc 同步"。但**单人接手场景**下 pre-commit hook 会显著降低 commit 速度（每次 5-10s）。GitHub Actions 上跑同样 check 更轻。
   - **建议**：**pre-commit hook 作为可选**（README 文档化安装），CI 作为硬约束；不要强制本地 hook。
   - **是否推翻 spec**：**部分推翻**——保留 hook 安装选项，但不在 spec 完成判据列为必需。
   - **action**：D.2.11 建议改。

4. **[PUSHBACK] P0-Hyg-cleanup `git bundle create ... --all` 不够**
   - 论据：同 C.1 #2，bundle restore 整库。工程师视角下，**更可靠的是 `git tag backup-pre-hygiene-2026-07-21 && git checkout backup-pre-hygiene-2026-07-21 -- <path>` 逐文件回滚**。
   - **action**：D.1.13 已包含（与 C.1 #2 合并）。

5. **[PUSHBACK] P0-Sec2 SSRF allowlist 仅 5 host 太脆**
   - 论据：spec §5.1 P0-Sec2 白名单 `api.openai.com / api.anthropic.com / api.mistral.ai / generativelanguage.googleapis.com` + 用户 custom 走 dev override。但**用户用本地 Ollama**（`http://127.0.0.1:11434/v1`）是合法场景，会被 SSRF 拒。
   - **建议**：加"本地 Ollama 例外"——host 是 `127.0.0.1` 或 `localhost` 且 port 在 known list（11434 / 1234 / 8080）允许，但强制走 loopback 不连外网。
   - **是否推翻 spec**：**否**——spec 当前默认拒 localhost；可加"Ollama 例外"子规则。
   - **action**：D.2.12 建议改。

6. **[PUSHBACK] P0-Sec5 "alembic batch_alter_table" 对 SQLite 仍不够**
   - 论据：SQLite 的 `ALTER TABLE ADD COLUMN` 支持有限（不能加 NOT NULL 无 default）。`batch_alter_table` 在 SQLite 下重命名表 + copy + drop，**对大表（>10k 行）非常慢**。spec §5.1 P0-Sec5 加 `base_url/model/is_active/use_env` 4 列 + data migration，provider 表通常 < 100 行——OK。但 spec 未说明 "如果 provider 表 > 1000 行需考虑其他方案"。
   - **建议**：spec 加一句注释说明 batch 模式在 SQLite 大表的限制；本仓库预估 provider 行数 < 100，OK。
   - **是否推翻 spec**：**否**——加注释即可。
   - **action**：D.2.13 建议改。

7. **[PUSHBACK] "每 P0 子项 1 个独立 PR" 与"按域合并 PR" 矛盾**
   - 论据：spec §5.1 P0-Sec1a "1 PR" + §5.1 P0-Sec1b "14 PR" 是同一 P0-Sec1 不同粒度，但读者容易混淆。
   - **建议**：spec 改为"P0-Sec1a 1 PR；P0-Sec1b 按 4 域合并 4 PR；P0-Sec1 整体共 5 PR"。
   - **action**：与 pushback #1 合并（D.2.4）。

### C.3 Existing-libraries re-examination
**status**：已收（c5d8a2e9b1f43706c）

> "对 spec 涉及的库选型做第二轮审视，确认是否真不造轮子。"

**审视结论**：

1. **Auth**：spec 用 stdlib + cryptography + keyring 是正确选择。**fastapi-users / authlib / python-jose 都过度工程**——fastapi-users 引入 SQLAlchemy User model + 注册流程 + 邮件验证，违反 single-user local app 假设。**C.3 结论：不引入外部 auth lib**。
2. **Provider registry**：**LiteLLM 引入 +20MB dep** + 抽象 50+ provider；本仓库只调 5 个（openai/anthropic/mistral/google/custom），手写 100 行代码即可。**LiteLLM 引入反而增加攻击面**（其内置 SSRF 防御可能与我们的不匹配）。**C.3 结论：拒绝 LiteLLM**。
3. **SSRF**：safehttpx / ssrf-protect 都是 kobotoolbox 内部工具，**API 不稳定**（最近 2 年无 release）；不适合 critical security 用途。**C.3 结论：用 stdlib**。
4. **IPC FS**：electron stdlib 足够。**无推荐外部 lib**。
5. **IndexedDB**：
   - **引入 `idb` (jakearchibald)** —— Promise wrapper + 显式错误传播，~3KB。
   - **引入 `fake-indexeddb` (shipp02)** —— Vitest 测试必备。
   - **不引入 `dexie` / `idb-keyval`** ——dexie 引入 query DSL（spec 不用）；idb-keyval 是 key-value wrapper 太薄。
   - **C.3 结论**：引入 2 个新 lib（idb + fake-indexeddb），明确拒绝 dexie/idb-keyval。
6. **AI cancel**：AbortController 是 stdlib，**无外部 lib 候选**。
7. **AI log**：**引入 `electron-log`** ——Electron 主进程专用 logger，提供 rotate + redact；spec 当前 console.log + 手动 JSONL 文件写入**会出 race condition**（多进程写同一文件）。
8. **CI**：**引入 `lint-staged`** ——只 lint staged files，pre-commit hook 必备。**拒绝 semgrep**（C.2 pushback 同源）。
9. **新增考虑项**：
   - `ajv` (JSON schema validator)——spec 当前 pydantic/zod 已覆盖，无需。
   - `joi` (Node schema validator)——同 ajv。
   - `crypto-js` (JavaScript crypto)——**拒绝**，浏览器内置 Web Crypto API 足够；crypto-js 历史上有 timing attack 漏洞。
   - `bcrypt` (Node password hash)——spec 不用密码，OS keychain 即可。

**C.3 总评**：spec 引入 4 个新 lib（`idb` + `fake-indexeddb` + `electron-log` + `lint-staged`），明确拒绝 5 个候选（`fastapi-users` / `LiteLLM` / `safehttpx` / `semgrep` / `crypto-js`）。

from urllib.parse import urlsplit
import ipaddress
import socket
import httpx
from cryptography.hazmat.primitives.ciphers.aead import AESGCM  # only for ticket binding

# Step 1: URL parsing + scheme check
def parse_url(url: str) -> tuple[str, str]:
    sp = urlsplit(url)
    if sp.scheme != "https":
        raise SSRFBlocked("scheme not https")
    if not sp.hostname:
        raise SSRFBlocked("no hostname")
    return sp.hostname, sp.path

# Step 2: hostname → allowlist check (known providers only)
HOST_ALLOWLIST = {
    "api.openai.com",
    "api.anthropic.com",
    "api.mistral.ai",
    "generativelanguage.googleapis.com",
    # user-supplied hosts ONLY via explicit dev override + audit log
}
# Exception: local Ollama for dev mode (C.2 pushback #5)
LOCAL_OLLAMA_HOSTS = {"127.0.0.1:11434", "localhost:11434", "127.0.0.1:1234", "localhost:1234"}

def is_allowlisted(host_port: str) -> bool:
    if host_port in LOCAL_OLLAMA_HOSTS:
        return True
    return host_port.split(":")[0] in HOST_ALLOWLIST

# Step 3: DNS resolve A + AAAA, REJECT if ANY record is non-global
def resolve_and_check(host: str) -> list[str]:
    infos = socket.getaddrinfo(host, None, type=socket.SOCK_STREAM)
    ips = []
    for fam, _, _, _, sa in infos:
        ip = sa[0]
        ip_obj = ipaddress.ip_address(ip)
        # IPv4-mapped IPv6 (::ffff:a.b.c.d) → unwrap and re-check
        if isinstance(ip_obj, ipaddress.IPv6Address) and ip_obj.ipv4_mapped:
            ip_obj = ip_obj.ipv4_mapped
        # NAT64 (64:ff9b::/96) → unwrap
        if isinstance(ip_obj, ipaddress.IPv6Address) and ip_obj.sixtofour:
            ip_obj = ipaddress.ip_address(str(ip_obj.sixtofour))
        if not ip_obj.is_global and host_port not in LOCAL_OLLAMA_HOSTS:
            raise SSRFBlocked(f"non-global IP: {ip}")
        ips.append(ip)
    if not ips:
        raise SSRFBlocked("no DNS")
    return ips

# Step 4: pin exact IP + rewrite URL (preserving Host for TLS SNI)
def pinned_request(url: str, ips: list[str], *, method="GET", **kw) -> httpx.Response:
    host, path = parse_url(url)
    # Round-robin among resolved IPs; pin first for now (writer is desktop, single connection)
    pinned_ip = ips[0]
    # Rewrite host to IP, keep Host header + SNI
    parsed = urlparse(url)
    rewritten = parsed._replace(netloc=pinned_ip).geturl()
    headers = kw.pop("headers", {})
    headers["Host"] = host  # for SNI + vhost
    with httpx.Client(
        follow_redirects=False,  # HARD: any 30x must NOT auto-follow
        timeout=10.0,
    ) as client:
        return client.request(method, rewritten, headers=headers, **kw)

import { randomBytes } from 'crypto';

interface TokenEntry {
  path: string;
  expiresAt: number;
  perm: 'read' | 'write';
}
const dialogTokenMap = new Map<string, TokenEntry>();
const TOKEN_TTL_MS = 60_000;  // 60 seconds
const TOKEN_BYTES = 32;        // 256-bit

function mintToken(path: string, perm: 'read' | 'write'): string {
  const token = randomBytes(TOKEN_BYTES).toString('base64url');
  dialogTokenMap.set(token, {
    path,
    expiresAt: Date.now() + TOKEN_TTL_MS,
    perm,

// src/frontend/src/store/utils/indexedDBStorage.ts
import { openDB, IDBPDatabase, DBSchema } from 'idb';

interface WriterDB extends DBSchema {
  kv: { key: string; value: unknown };
  meta: { key: string; value: { size: number; lastPruned: number } };
}

const DB_NAME = 'writer-storage';
const DB_VERSION = 1;
const SOFT_LIMIT_BYTES = 50 * 1024 * 1024;   // 50MB
const HARD_LIMIT_BYTES = 100 * 1024 * 1024;  // 100MB

export class IndexedDBStorageError extends Error {
  constructor(public kind: 'quota' | 'private-mode' | 'corruption' | 'blocked' | 'unknown', message: string) {
    super(message);
  }
}

export const indexedDBStorage = {
  async getItem(key: string): Promise<unknown | null> {
    try {
      const db = await this._openDB();
      const tx = db.transaction('kv', 'readonly');
      const value = await tx.objectStore('kv').get(key);
      await tx.done;
      // not-found is NOT an error — return null
      return value === undefined ? null : value;
    } catch (e) {
      // corruption / blocked / unknown → THROW, not swallow
      throw this._classifyError(e);
    }
  },

  async setItem(key: string, value: unknown): Promise<void> {
    try {
      const db = await this._openDB();
      const tx = db.transaction('kv', 'readwrite');
      await tx.objectStore('kv').put(key, value);
      await tx.done;
      await this._maybePrune();
    } catch (e) {
      // quota / corruption → THROW, propagate to UI banner
      throw this._classifyError(e);
    }
  },

  async removeItem(key: string): Promise<void> {
    try {
      const db = await this._openDB();
      const tx = db.transaction('kv', 'readwrite');
      await tx.objectStore('kv').delete(key);
      await tx.done;
    } catch (e) {
      throw this._classifyError(e);
    }
  },

  async _openDB(): Promise<IDBPDatabase<WriterDB>> {
    return await openDB<WriterDB>(DB_NAME, DB_VERSION, {
      upgrade(db) {
        if (!db.objectStoreNames.contains('kv')) db.createObjectStore('kv');
        if (!db.objectStoreNames.contains('meta')) db.createObjectStore('meta');
      },
    });
  },

  _classifyError(e: unknown): IndexedDBStorageError {
    if (!(e instanceof Error)) return new IndexedDBStorageError('unknown', String(e));
    const name = (e as any).name ?? '';
    if (name === 'QuotaExceededError') return new IndexedDBStorageError('quota', e.message);
    if (name === 'InvalidStateError') return new IndexedDBStorageError('corruption', e.message);
    if (name === 'VersionError') return new IndexedDBStorageError('blocked', e.message);
    if (name === 'UnknownError' && /private/i.test(e.message)) return new IndexedDBStorageError('private-mode', e.message);
    return new IndexedDBStorageError('unknown', e.message);
  },

  async _maybePrune(): Promise<void> {
    // 跨阈值原子清理：HARD 触发时清最旧 25% entries（all-or-nothing）
    const db = await this._openDB();
    const size = await this._estimateSize();
    if (size > HARD_LIMIT_BYTES) {
      const tx = db.transaction(['kv', 'meta'], 'readwrite');
      const allKeys = await tx.objectStore('kv').getAllKeys();
      const sortedKeys = allKeys.sort();  // TODO: 用 LRU 排序
      const toDelete = sortedKeys.slice(0, Math.ceil(sortedKeys.length / 4));
      for (const k of toDelete) await tx.objectStore('kv').delete(k);
      await tx.objectStore('meta').put({ size: 0, lastPruned: Date.now() }, 'prune');
      await tx.done;
    }
  },

  async _estimateSize(): Promise<number> {
    if (navigator.storage?.estimate) {
      const est = await navigator.storage.estimate();
      return est.usage ?? 0;
    }
    return 0;
  },
};
