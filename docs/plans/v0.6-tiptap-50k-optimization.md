## §1 背景

### 1.2 用户场景

中国网文作者典型工作流：
- 单章 5k-10k 字（普通章节）

- 整书 100k-500k 字（中等长篇）

**关键性能指标**（基于 v0.5 baseline 推算）：
- 单章 10k 字：编辑/保存应该 < 100ms
- 单章 50k 字：编辑 < 300ms；保存 < 1s
- 单章 100k 字：编辑 < 1s；保存 < 2s

## §2 当前限制分析

### 2.1 Tiptap / ProseMirror 性能瓶颈

Tiptap 基于 ProseMirror，文档结构是单一树形 JSON：

```json
{
  "type": "doc",
  "content": [
    { "type": "paragraph", "content": [...] },
    { "type": "heading", "content": [...] },
    ...
  ]
}
```

**性能特性**：

| 操作 | 10k 字 | 50k 字 | 100k 字 |
|------|--------|--------|---------|
| 初始渲染（FCP） | ~50ms | ~250ms | ~600ms |
| 输入延迟（keystroke） | <16ms | ~30-50ms | 80-150ms |
| 全选+删除 | ~80ms | ~500ms | ~2s |
| 复制粘贴 100 字 | <30ms | ~80ms | ~200ms |

**瓶颈**：
- 单 ProseMirror 树重建代价 O(n)
- DOM 节点数与字符数近似（1 char ≈ 1-3 nodes）
- 每次 input 触发 transaction → 全树 diff

### 2.2 IndexedDB 写入瓶颈

当前 useEditorAutosave：

```typescript
const debouncedSave = debounce(async (content: string) => {
  const blob = new Blob([content], { type: 'text/html' });
  await set('editor:draft', { content: blob, savedAt: Date.now() });
}, 3000);
```

**单次写入**：50k 字 ≈ 200KB blob。IDB 事务 commit ~ 100-300ms。

**风险**：
- 主线程阻塞（IDB 写入是 async 但 large blob serialization 是 sync）
- 多次快速编辑触发多个事务 contention

### 2.3 保存策略无 chunking

当前整章保存为单 blob。**网络恢复** / **增量同步** / **diff preview** 都不可行。

## §3 50k 字专项优化方案

### 3.1 优化总览

```
┌─────────────────────────────────────────────────────────┐
│  Editor (Tiptap)                                         │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ │
│  │ ProseMirror  │  │ Custom       │  │ Y.js CRDT    │ │
│  │ (current)    │  │ V-Node Tree  │  │ (new)        │ │
│  └──────────────┘  └──────────────┘  └──────────────┘ │
└─────────────────────────────────────────────────────────┘
            ↓                    ↓                  ↓
┌─────────────────────────────────────────────────────────┐
│  Storage Layer                                          │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ │
│  │ Chunked IDB  │  │ OpLog (CRDT) │  │ Snapshot     │ │
│  │ (5k chunks)  │  │ (delta)      │  │ (full text)  │ │
│  └──────────────┘  └──────────────┘  └──────────────┘ │
└─────────────────────────────────────────────────────────┘
```

### 3.2 Y.js CRDT 增量协同

虽然不需要 multi-user 协同，**CRDT 提供 O(1) 编辑 / O(log n) merge**：

- **增量编码**：每次编辑生成 small Y.js update（几字节到几 KB）
- **本地优先**：所有编辑在本地 Y.Doc，无 server roundtrip
- **未来扩展**：如果 Phase 3+ 加 multi-device sync，Y.js 提供天然 merge

**实施方案**：

```typescript
// 替换 Tiptap document state 为 Y.Doc
import { TiptapCollaboration } from '@tiptap/extension-collaboration'
import { ySyncPlugin } from 'y-prosemirror'
import * as Y from 'yjs'

const ydoc = new Y.Doc()
const provider = new IndexeddbPersistence(`chapter-${id}`, ydoc)  // auto-save to IDB

const editor = useEditor({
  extensions: [
    StarterKit.configure({ history: false }),  // Y.js handles history
    Collaboration.configure({ document: ydoc }),
  ],
})
```

**优势**：
- IDB 自动持久化（Y.js IndexeddbPersistence）
- Delta-based updates（不重写全文）
- 协同 ready（Phase 3+ 加 multi-device 只需加 provider）

**权衡**：
- Bundle size +30KB (yjs + y-prosemirror)
- 学习曲线（团队需了解 Y.Doc API）

### 3.3 Tiptap ProseMirror 节点树扁平化

针对 > 30k 字章节，减少 reflow：

- **段落块合并**：相邻同类型 paragraph 合并（DOM 节点 -50%）
- **OffscreenCanvas 渲染**：长段落使用 canvas 替代 DOM（experimental）
- **Mark 合并**：相邻同 mark 文本合并

**Phase 1 实施**：仅 paragraph 合并（最低风险）
```typescript
// Custom extension: 段落块合并
const BlockMergeExtension = Extension.create({
  name: 'blockMerge',
  // 在 transaction commit 时合并相邻同类型 paragraph
})
```

### 3.4 虚拟滚动编辑器（experimental）

仅渲染 viewport + 缓冲区（10 屏上下）：

- **视口检测**：`IntersectionObserver` 监听 paragraph visibility
- **懒挂载**：scroll 出 viewport 的 paragraph → unmount DOM 节点（保留 PM state）
- **占位元素**：保持滚动条高度稳定

**风险**：
- Tiptap 内部 mutation API 不友好
- 选区（selection）跨 viewport 时行为异常
- 光标移动可能 laggy

**建议**：Phase 2 后期 + benchmark，**不作为 v0.6 必做项**。

### 3.5 Chunked Save（核心方案）

**当前**：整章 1 个 blob。

**目标**：5k 字为单元，分批写入 IDB：

```typescript
interface ChapterChunk {
  id: string;          // hash(content)
  chapter_id: number;
  position: number;    // 0..N
  content: string;     // 5000 字
  word_count: number;
  created_at: number;
}

interface ChapterManifest {
  chapter_id: number;
  total_chunks: number;
  total_words: number;
  fingerprint: string;  // sha256(concatenated content)
  version: number;
}
```

**写入流程**：

```typescript
async function saveChapterChunks(chapterId: number, fullText: string) {
  const chunks = chunkText(fullText, 5000)  // split by paragraphs to 5000-word units
  const tx = db.transaction(['chunks', 'manifest'], 'readwrite')
  
  // Delete old chunks (incremental update preserves history via oplog)
  await tx.objectStore('chunks')
    .index('by-chapter').delete(IDBKeyRange.only(chapterId))
  
  // Write new chunks in batch
  for (const chunk of chunks) {
    await tx.objectStore('chunks').put(chunk)
  }
  
  // Update manifest
  await tx.objectStore('manifest').put({
    chapter_id: chapterId,
    total_chunks: chunks.length,
    total_words: fullText.split(/\s+/).length,
    fingerprint: sha256(fullText),
    version: now(),
  })
  
  await tx.done
}
```

**优势**：
- 单 chunk write ≈ 30ms（vs 整章 200-500ms）
- Failed write 只影响 1 chunk（vs 整章失败）
- 后台分批执行（不阻塞编辑）

**IDB schema 迁移**：

```typescript
// v0.6 schema bump from v1 to v2
db.version(2).stores({
  chunks: 'id,chapter_id,[chapter_id+position]',
  manifest: 'chapter_id',
  // 保留旧 draft 表（向后兼容）
})
```

### 3.6 后台协作式保存

**Worker Pattern**：

```typescript
// useChunkedAutosave hook
const saveQueue = useRef<ChunkSaveJob[]>([])
const isProcessing = useRef(false)

async function enqueueSave(chapterId: number, content: string) {
  saveQueue.current.push({ chapterId, content, ts: Date.now() })
  if (!isProcessing.current) {
    isProcessing.current = true
    await processQueue()
    isProcessing.current = false
  }
}
```

**触发条件**：
- 编辑停顿 3s → 触发 save
- 单 chunk 写失败 → 重试 3 次
- 离线 → 暂停写 + 标记 dirty

### 5.2 性能基准

```typescript
// bench/editor-50k.ts
import { performance } from 'perf_hooks'

async function benchmark() {
  const chapter = await load50kChapter()
  
  // FCP
  const startFCP = performance.now()
  await editor.commands.setContent(chapter.html)
  const FCP = performance.now() - startFCP
  
  // keystroke latency (平均 100 次)
  let totalLatency = 0
  for (let i = 0; i < 100; i++) {
    const start = performance.now()
    editor.commands.insertContent('字')
    totalLatency += performance.now() - start
  }
  const avgKeystroke = totalLatency / 100
  
  // save latency
  const startSave = performance.now()
  await saveChapter(chapter.id, chapter.text)
  const saveLatency = performance.now() - startSave
  
  return { FCP, avgKeystroke, saveLatency }
}
```

| Keystroke latency | < 16ms | < 30ms | < 50ms |
| Save latency | < 500ms | < 1s | < 2s |
| IDB write per chunk | < 30ms | < 60ms | < 100ms |

## §6 风险

### 6.1 Y.js 集成风险

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| Tiptap + Y.js API mismatch | 中 | POC 验证（Sub-task 5/6） |
| Y.js 持久化与现有 IDB 冲突 | 中 | 独立 namespace（`chapter-{id}` per doc） |
| Bundle size +30KB | 低 | 可接受（现有 bundle 800KB） |

### 6.2 Chunked save 风险

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| Chunk 边界切分错误（段落断裂） | 高 | 按段落切分 + 单元测试 |
| 事务 contention（并发写） | 中 | 串行化 save queue |
| Crash 中途（部分 chunk 写入） | 中 | Manifest 版本号 + 启动时校验 |
| 老章节（v0.5 单 blob）迁移 | 低 | 自动 detect + lazy upgrade |

### 6.3 虚拟滚动风险（不推荐 v0.6 实施）

| 风险 | 严重度 |
|------|--------|
| Selection 跨 viewport 行为异常 | 高 |
| 光标移动 laggy | 高 |
| Tiptap 内部 mutation API 不友好 | 高 |
| 实现复杂度高 | 高 |

## §10 兼容性 / 回滚策略

### 10.1 兼容性矩阵

| 旧版本 | 升级路径 | 数据迁移 |
|--------|----------|----------|
| v0.5 (单 blob) | v0.6 (chunked) | 自动 detect `editor:draft` → lazy 拆分到 chunks |
| v0.6.0 | v0.6.1 (Y.js) | Y.js doc 初始化 from chunked manifest |
| v0.6.x | v0.7+ | 保留 chunked schema，添加 opLog |

### 10.2 回滚方案

如果 v0.6.1 Y.js 集成出现严重问题：

1. **保留 chunked save**（Sub-task 1-4 独立可用）
2. **回滚 Y.js 部分**（revert Tiptap config + 移除 yjs dependency）
3. **autosave hook 改为 chunked-only**（无 Y.js）

回滚后仍有性能提升（chunked save），只是失去 CRDT delta 优势。
